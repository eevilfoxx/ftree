# Progress: architecture and build repair

## Этап: исправление низкозависимых компонентов и интеграция доменного ядра

**Дата:** 2026-11-18

### Выполнено

- Исправлен `domain::Person`:
  - удалена фиктивная реализация смерти на общем статическом счётчике;
  - добавлена проверка `canConceive()`;
  - беременность невозможна у мужчин и умерших персонажей;
  - полный конструктор нормализует недопустимое состояние беременности.
- Исправлен `domain::Family`:
  - реализованы объявленные методы управления детьми;
  - повторное добавление ребёнка не создаёт дубликат;
  - исключены нулевые ID и ID родителей в списке детей;
  - `getAllMembers()` возвращает уникальных участников.
- Исправлены `World` и семейные связи:
  - новые персонажи изначально не беременны;
  - создание семьи проверяет существование, пол, жизнь и семейное состояние родителей;
  - ID персонажей и семей монотонны и не переиспользуются после расформирования;
  - расформирование семьи очищает связи и удаляет запись семьи;
  - список участников семьи не содержит дубликатов.
- Исправлены старые `entities::Person` / `entities::Family`:
  - имя и фамилия возвращаются по `const std::string&`;
  - добавление ребёнка стало идемпотентным;
  - при переносе ребёнка удаляется его членство в предыдущей семье;
  - очищаются истёкшие weak-ссылки;
  - добавление родителей в список детей запрещено.
- Переработан `FamilyManager`:
  - проверяются повторные браки и нулевые аргументы;
  - ID семьи выбирается без коллизий после удаления;
  - расформирование очищает связи родителей и детей;
  - события не разыменовывают отсутствующих родителей;
  - перенос ребёнка синхронизирует оба репозитория.
- Исправлен `PopulationManager`:
  - возраст самого кандидата проверяется и по нижней, и по верхней границе;
  - родитель и ребёнок распознаются как близкие родственники наряду с полными и неполными братьями/сёстрами.
- Реализованы доменные системы симуляции:
  - смерть рассчитывается по формуле смертности и внедрённому генератору случайных чисел;
  - зачатие использует возрастную функцию фертильности, ограничения и конфигурируемую вероятность;
  - рождение поддерживает одиночные, двойные и тройные роды;
  - родившиеся дети получают корректные ссылки на родителей и запись в семье происхождения;
  - добавлена система браков с проверкой возраста, пола, семейного статуса, близкого родства и вероятности по разнице возрастов.
- Исправлен `SimulationConfig`:
  - реализованы `getInt`, `getDouble`, `getString` и `has`;
  - парсер обрабатывает пробелы, комментарии и некорректные числовые значения;
  - добавлена проверка конечности вероятностей и согласованности возрастных ограничений.
- Исправлены `Random::seed()` и `SimulationClock::reset()`.
- Обновлён `Application`:
  - результат `loadFromFile()` теперь действительно сохраняется;
  - пути к файлам имён разрешаются относительно конфигурационного файла;
  - начальные имена и возраст берутся из загруженных ресурсов и конфигурации;
  - годовая последовательность выполняет старение → смерти → браки → беременности → рождения → статистику;
  - реализованы `setSpeed()` и `update()`, обновляется год симуляции.
- Перестроен `CMakeLists.txt`:
  - выделена самостоятельная статическая библиотека `ftree_core`, не зависящая от SFML;
  - приложение линкуется с `ftree_core`;
  - убраны дублирующиеся записи тестового исходника;
  - добавлены доменные и core-тесты;
  - при отсутствии GoogleTest конфигурация ядра не блокируется.
- Удалены устаревшие объявления неиспользуемых методов из `Scene`, инициализировано состояние `Visualizer::showControls_`; исправлены include для `std::clamp` и имя SFML primitive `sf::LineStrip`.

### Ограничения проверки

- В среде нет GoogleTest: `FamilyTreeTests` не был собран, CTest-набор не запускался.
- В среде нет SFML: реальная графическая цель `FamilyTree` не собиралась и не запускалась. Проверка `Application.cpp` с заглушками не заменяет сборку против настоящего SFML.
- Проверялась только Linux-среда с GCC 14.2; MSVC/Windows CI не запускался.
- Исходный архив содержал `.git`; активная ветка уже `rewrite/architecture`.
- В рабочем дереве до наших изменений присутствовали многочисленные пользовательские изменения и untracked-файлы. Новые коммиты не создавались, чтобы случайно не включить их в коммит.
- В итоговый ZIP `.git` не включён, чтобы не перезаписывать метаданные локального репозитория пользователя.

### Оставшиеся проблемы

1. Старая реализация `entities/services/managers` и новая `domain/simulation` пока существуют параллельно. Полная миграция и удаление дублирующихся API не выполнены.
2. `Application` пока не интегрирован с полноценным `Visualizer`: его собственный `render()` очищает окно и выводит пустой кадр. Графический слой требует отдельной интеграции.
3. Не все элементы управления визуализатора связаны с новым `Application`.
4. Новая система браков пока не публикует доменные события через `EventDispatcher`.
5. `NameDatabase` пока возвращает первое загруженное имя/фамилию, а не выбирает случайное значение.
6. Необходимо прогнать полный набор GoogleTest в CI и выполнить настоящую сборку с SFML на Windows и Linux.
7. Smoke-прогон на 100 лет с текущим фиксированным seed и четырьмя основателями завершился вымиранием популяции. Это не ошибка сборки, но демографические параметры и размер начальной популяции требуют отдельной калибровки.
8. Нужны дополнительные тесты на долгие симуляции, граничные значения конфигурации, семейные связи после смерти/расформирования и воспроизводимость всего годового цикла.
